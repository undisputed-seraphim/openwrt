# RTL8198C — gigabit switch SoC

Five-port 10/100/1000 switch core with an integrated MIPS 1074Kc CPU, a
descriptor-ring "CPU interface" between the two, and five internal GbE
PHYs.  This file is the chip reference: what each block can do, how it is
driven here, and whether this driver uses it.

The tables are split by layer.  **Standard** names the specification that
defines the feature where one exists (vendor-specific features are marked
"—").  **Done** means:

| Mark | Meaning |
|------|---------|
| ✓ | implemented and verified on the AP5100W |
| partial | implemented for a subset, or the hardware only does part of it |
| ✗ | not implemented — the cell says whether the hardware could |
| n/a | not applicable on this board |

## Driver layout — BSP mapping

`target/linux/realtek/files-6.18/drivers/net/ethernet/rtl8198c/`.  When
comparing against the vendor source, start from the block, not the
function: the table functions keep their BSP shape, and every exported
symbol carries the `rtl8198c_` prefix.

| `rtl8198c_phy.c` | MDIO, GPHY SRAM98C patches, `phy_refine()` NCTL calibration, power/green, ethtool link settings | `Setting_RTL8198C_GPHY()`, `phy_refine()`, `get/setAsicEthernetPHYReg()` |

Inside a block the function names are unchanged from the single-file
driver (`l2_fdb_add()`, `eth_poll()`, …), so `git log -S` finds them.
`dma.c` holds the whole per-packet path: its only cross-file calls are
the `static inline` MMIO accessors in `rtl8198c.h`, which is deliberate,
since the data path is CPU-bound.

## Kernel interface — CPU data path

The host-facing half: how frames move between Linux and the switch core.
Every RX and TX descriptor is a 32-byte `pkthdr` pointing at 24-byte
`mbuf`s (see "Descriptor format"), and the RISC firmware walks the rings
in uncached KSEG1 memory.

| Feature | Standard | How it works | Done |
|---|---|---|---|
| Per-port netdevs | — | Five netdevs (`eth0`..`eth4` = ports 0-4) over one CPU interface and one ring set.  Port 0 is the WAN port in VLAN 8, ports 1-4 are LAN in VLAN 9; the CPU is in both.  Each netdev has its own MAC and counters. | ✓ |
| RX attribution | — | Ingress port comes from `ph_portlist & 7`; a plain netdev takes frames addressed to it (or flooded), a bridge-enslaved port takes every frame that arrives on it. | ✓ |
| Descriptor engine | — | Legacy pkthdr/mbuf format (the 8198C does not use the "new descriptor" layout).  A ring entry is a KSEG1 pointer plus the OWN and WRAP bits. | ✓ |
| RX rings | — | Six 256-entry rings, one per switch queue, sharing one linear mbuf ring (`CPURPDCR0-5`, `CPURMDCR0`).  Queue→ring is `CPUQDM`, priority→queue is `CPUQIDMCR0`. | ✓ |
| TX rings | 802.1p class selection | Two 256-entry rings; `skb->priority >= 4` uses ring 1, which is also egress queue 1.  `TXFD` in `CPUICR` is the per-packet doorbell. | ✓ |
| Interrupts and NAPI | — | One IRQ (virq 18, GIC hwirq 32) for RX done, TX done and link change; NAPI polls every ring with a per-ring budget. | ✓ |
| RX zero-copy | — | The RISC writes the frame straight into `skb->data`; `napi_alloc_skb()` refills the mbuf.  Received skbs are keyed by mbuf index, because the RISC rewrites `ph_mbuf` to the shared-ring entry it used. | ✓ |
| RX buffer sizing | — | 2 KB per buffer at MTU 1500, 10 KB for jumbo; the ring is shared, so the size follows the largest port MTU and is rebuilt on an MTU change without stopping TX. | ✓ |
| TX scatter-gather | — | A fragmented skb becomes an `m_next` chain (head + one spare mbuf per fragment, `MBUF_EOR` plus 4 CRC bytes on the last).  `NETIF_F_SG`; `frag_list` and over-long chains are linearised. | ✓ |
| MTU change | — | `ndo_change_mtu` (1500-9000) rebuilds the RX ring, updates PCRP `AcptMaxLen` and the netif-table MTU. | ✓ |
| MAC address | — | Taken from the device tree `local-mac-address` (with a random fallback) and movable with `ip link set address`, which rewrites the L2 and netif entries.  The board's factory address is never read from EEPROM or NAND, so the device-tree value is the placeholder. | ✓ |
| 64-bit statistics | — | Per-CPU `pcpu_sw_netstats` behind `ndo_get_stats64`, plus per-port link/1G and per-ring/per-queue counters on `ethtool -S`. | ✓ |
| ethtool control | — | Link ksettings (force speed/duplex, advertise, N-way restart), statistics, `tx_maxrate`. | ✓ |
| Debugfs control surface | — | One `switch/` directory for the shared knobs (FDB, VLAN, ACL, multicast, storm, mirror, rate, DSCP, registry access) plus per-port state. | ✓ |
| Link state / carrier | — | `PSRP0 + port * 4` bit 4 is the switch's own link state.  One `LINK_CHANGE_IP` covers all five ports, so the NAPI poll rescans the registers and drives `netif_carrier_on/off`; the same scan runs at open, because the interrupt only reports changes. | ✓ |

## L1 — PHY and link

Five internal GbE PHYs behind one MDIO controller (PHY addresses 8, 1, 2,
3, 4 for ports 0-4).

| Feature | Standard | How it works | Done |
|---|---|---|---|
| 10/100/1000BASE-T | 802.3i/u/ab | Five internal GPHYs; MDIO through `MDCIOCR`/`MDCIOSR`. | ✓ |
| N-way auto-negotiation | 802.3 cl. 28 | PCRP `NwayAbility` advertises all five modes; PHY reg 9 bit 9 is written explicitly for 1000BASE-T full, then `BMCR` restart. | ✓ |
| 1000BASE-T signal path | 802.3ab | Needs the NCTL DSP calibration (`phy_98c_para[]`, 19 register pairs) plus RC/R and ADC-bias values from the SoC efuse; without it the PHY never trains. | ✓ |
| Auto-down-speed | 802.3 (2-pair fallback, vendor) | With only two pairs in the cable the GPHY drops its 1G advertisement and links at 100M. | ✓ |
| Link status readout | 802.3 cl. 22 | `BMSR` plus the 1G status bits, exported by `ethtool` and `ethtool -S`. | ✓ |
| Link-change interrupt | — | Bit 31 of `CPUIIMR`/`CPUIISR`, one for the whole switch - the event does not name the port, so the handler rescans `PSRP0-4`.  The ISR masks it and the NAPI poll re-arms it; no port needs a MAC write on a transition. | ✓ |
| 802.3x pause | 802.3x | The MAC generates and honours pause with `MACCR` infinite-pause and `FCDSC` set to 48 pages, and the system/port/queue thresholds are programmed.  PAUSE capability is not advertised in `MII_ADVERTISE` and there is no `ethtool -A`, so a link partner will not send pause. | partial |
| Green Ethernet | 802.3az-adjacent (vendor) | SRAM98C table enables cable-length power saving at 1G and 100M; debugfs `green` switches it.  The table is write-only. | ✓ |
| Per-PHY power-down | 802.3 (BMCR power down) | Debugfs `phy_power` takes a 5-bit mask; sets `BMCR` power-down and the PCRP force-mode/link-poll state so the MAC stops reporting a link. | ✓ |
| EEE (low-power idle) | 802.3az | Would need per-port writes to PHY pages 32/33/40/64/65/66 and a renegotiation.  Unverifiable here: no EEE-capable link partner. | ✗ |
| Giga Lite (500M) | — | Vendor half-step mode via `EXTPCR`/GPHY write-back pages.  Unverifiable here: needs a partner that supports it. | ✗ |
| Cable diagnostics (TDR) | — | The vendor implementation is compiled only for the 8197F, so 8198C support is unproven — this needs an experiment before it is a task. | ✗ |
| Port LEDs | — | `LEDCR0` in direct mode drives link/activity on the RJ45 LEDs. | ✓ |
| External PHY on port 5 | — | The core can drive a sixth port, but the AP5100W wires only the five internal GPHYs, so the external interface is unused. | n/a |

## L2 — switching

Store-and-forward fabric with a 1024-entry, 4-way hash FDB (256 rows × 4
columns), four filtering databases and 4096 VLAN table entries.

| Feature | Standard | How it works | Done |
|---|---|---|---|
| Bridging across ports | 802.1D | Hardware forwards between the five ports at wire speed; the CPU is an extension port that can be made a member of any VLAN. | ✓ |
| MAC learning | 802.1D | The FDB learns source MACs on ingress; the hash row is the XOR of the MAC octets, salted per filtering database. | ✓ |
| Aging | 802.1D | Hardware ages in 150 s steps and keeps a 2-bit age class per entry; there is no global aging-time register, only disable and fast modes (debugfs `l2_aging`). | ✓ |
| Static / pinned FDB entries | 802.1D, `bridge fdb` | TACI `CMD_FORCE` writes; `ndo_fdb_add/del/dump` and `ndo_fdb_del_bulk` expose add/del/show/flush, debugfs `fdb` pins a MAC to a port mask. | ✓ |
| Flooding | 802.1D | Unknown unicast, broadcast and (unregistered) multicast flood inside the VLAN.  `FFCR`'s TOCPU bits do not gate CPU delivery on this core — the CPU receives because it is a VLAN member. | ✓ |
| VLANs | 802.1Q | TACI type 6 entries (`VCR0` ingress filtering, `PVCR0-4` PVIDs).  Four filtering databases, a hardware limit, so at most four VLANs can keep separate MAC tables. | ✓ |
| VLAN tag stripping | 802.1Q | Egress untag mask, per port plus the CPU bit.  The hardware strips tags, it never inserts one, so a VLAN device's traffic keeps its tag towards the CPU. | partial |
| 802.1Q-in-802.1Q | 802.1Q | Works: the outer tag is classified and both tags are delivered. | ✓ |
| QinQ with 802.1ad TPID | 802.1ad | Not possible: the parser only recognises 0x8100 and the register set has no outer-tag or TPID field. | ✗ |
| Protocol-based VLAN | 802.1v | Six ingress rules per port: IPX, NetBIOS and PPPoE control/session are fixed in hardware, two more take a user EtherType.  The built-in IPX rule matches 802.2 LLC (DSAP 0xE0), not EtherType 0x8137. | ✓ |
| Priority / 802.1p | 802.1p | Each port has two egress queues; priorities 0-3 map to queue 0 and 4-7 to queue 1 (`UPTCMCR1`).  A DSCP→priority table (`DSCPCR0-6`) is programmable per port, but nothing maps a frame's 802.1p PCP into a queue: priority comes from `skb->priority` and the DSCP table only. | partial |
| Queue scheduling | — (vendor WFQ) | The PSCR block has per-queue rate guarantees and weighted fair queueing; the driver programs the vendor defaults and has no `tc` integration. | partial |
| Egress rate limiting | — (token bucket) | Per port (`WFQRCRP0`, 64 kbps units) and per queue (`PnQmRGCR`: average, burst, peak).  Control path is `ndo_set_tx_maxrate` and debugfs `rate`. | ✓ |
| Ingress rate limiting | — | `IBCR0-2` accept writes but do not meter on this core (measured: 16 kbps per port still passed line rate), so no knob is exposed. | ✗ |
| Storm control | — | Broadcast and multicast meters: `BSCR` byte budget plus per-port `PCRP` enable bits; debugfs `storm`.  There is no unknown-unicast meter on this core. | ✓ |
| Port mirroring | — | `PMCR` destination port plus ingress/egress source masks; the CPU (port 6) can be the destination, which makes single-cable captures possible. | ✓ |
| Spanning tree states | 802.1D | `PCRP` bits 5:4 hold the state (disable/blocking/learning/forwarding; listening shares the blocking encoding) and it latches directly - the BSP's `EnForceMode` double toggle is an 8196C workaround that compiles to nothing here.  `MSCR.EN_STP` makes the switch enforce the states, and `RMACR.MADDR00` traps BPDUs to the CPU whatever the ingress port's state, so a blocked port can still take part in the election.  Both switch on while a port is bridged, and the states arrive as switchdev port attributes from `br_set_state()`. | ✓ |
| RSTP / MSTP | 802.1w / 802.1s | Same four port states, for one spanning tree: the hardware holds a single state per port (`PCRP` bits 5:4), so only the CIST is enforced and an MST instance has no hardware state of its own.  RSTP then needs nothing beyond those states plus a user-space daemon (`mstpd`); MST per instance cannot be offloaded.  Not exercised here: the image has no `mstpd` and one cable cannot form a loop. | partial |
| Port authentication | 802.1X | `DOT1X` registers and the guest-VLAN control exist; the driver only clears them during reset.  Unverifiable here: needs a supplicant and an 802.1X-capable peer, and the FDB entry builder would have to grow the auth bit. | ✗ |
| Link aggregation | 802.3ad / 802.1AX | Not possible: no usable LAG block.  `0x4C00-0x4CFF` is an unlisted hole in this core's register map, the vendor firmware contains no trunk code, and writing the inherited `LAGCR0` mask blackholes egress to the named ports.  Linux bonding still works in software; debugfs `lag` says so. | ✗ |
| ACL (ingress) | — (vendor) | TACI type 12, 252 usable entries, walked as a per-netif chain with a default chain for bridged traffic; MAC and IPv4 rules with permit/drop/to-CPU; debugfs `acl`.  No priority or rate action. | ✓ |
| ACL (egress) | — | Disabled by the vendor for a hardware bug; `EN_OUT_ACL` is never set. | ✗ |
| Multicast steering | — | A group is a static L2 entry for its derived MAC (`01:00:5e:…`, `33:33:…`) with a port mask and a CPU copy.  The bridge's `PORT_MDB` objects feed it (`rtl8198c_mcast_mdb_add/del`), and debugfs `mcast` programs groups the bridge does not know. | ✓ |
| IGMP/MLD snooping | RFC 4541 / RFC 3810 | The bridge snoops in software and its `PORT_MDB` objects reach the switch as L2 entries with the joined port's mask plus a CPU copy - the copy is what lets the bridge keep seeing the reports and queries that hold the group open.  `HOST_MDB` needs nothing extra because of that copy. | ✓ |
| PPPoE pass-through | RFC 2516 | `ALECR` `EN_PPPOE` lets the hardware encapsulate/decapsulate PPPoE headers. | ✓ |
| Protocol parser | — | `SWTCR1` enables VLAN/SNAP/PPPoE/IP/TCP/UDP/IGMP parsing, which the ACL and QoS stages depend on. | ✓ |
| Jumbo frames | — (vendor extension) | Up to 9 KB: PCRP `AcptMaxLen` on every port plus the CPU, a GPHY page-0 register-23 workaround, and 10 KB RX buffers. | ✓ |
| MAC filtering | 802.1D | A static entry at the MAC's hash row with a zero member mask drops that MAC in both directions; debugfs `mac_filter`. | ✓ |
| Bridge interop | 802.1D | A `br-lan` over ports works, with the ports registered as switchdev offload ports (`ndo_get_port_parent_id`, `switchdev_bridge_port_offload`, `tx_fwd_offload`).  Frames the switch flooded are marked `offload_fwd_mark`, so the software bridge does not send a second copy; the two hardware domains are the two filtering databases, which keeps a bridge that spans them correct.  The bridge's FDB still only learns from those floods because known unicast never reaches the CPU.  Bridge VLAN filtering takes the 802.1q fallback (`ndo_vlan_rx_add_vid`): the port joins the VLAN - untagged only when it is the port's native VLAN - but the bridge's pvid/untagged metadata is not conveyed.  Port flags - learning, the three flood bits, isolated, hairpin, locked - stay in software: the ASIC has no per-port control for any of them and keeps forwarding regardless.  Enslaving adds the bridge's VID 1, which consumes one of the four filtering databases. | ✓ |
| Port isolation / private VLAN | 802.1Q (PVLAN is vendor) | No dedicated register found and nothing implemented; ebtables/nftables does the filtering, and ACL MAC rules can approximate it per port pair. | ✗ |
| Loop detection | 802.1D | Not possible: this core has no loop-detection block - nothing in the register map or the vendor code.  STP is the mechanism, and its port states are enforced. | ✗ |
| PTP timestamping | 802.1AS / IEEE 1588 | Not possible as a timestamping feature: the PTP block (`PTP_BASE = SWCORE + 0x4E00`) is a 32-bit free-running counter (`STR0`) that the vendor uses only as a timer for force-MDIX.  There is no capture or latch path, no clock registration and no reference implementation. | ✗ |

## L3 — routing

The core has a full IPv4 routing engine: a prefix table, an ARP table, a
next-hop table and an (S,G) table, all reached through TACI.  The driver
mirrors the kernel's FIB and programs the routes the hardware can carry;
everything else stays in the kernel and reaches it through the CPU default
route at index 7.

| Feature | Standard | How it works | Done |
|---|---|---|---|
| IPv4 routing | RFC 1812 | The route table (type 2) is a priority list of 8 prefixes: the lookup walks it from index 0, so entries are sorted longest-prefix-first and index 7 is the default route (pointing at the CPU when the kernel's default is not offloaded).  A route names an egress netif and one of: an ARP block (on-link), a next-hop group (gateway), the CPU, or drop.  Off by default - see the note below. | ✓ |
| ARP table | RFC 826 | 512 entries.  An on-link prefix owns a contiguous block of `2^(32-len)` entries and the hardware indexes it with the host part of the destination, so on-link prefixes must be /23 or longer; the block exists before its neighbours.  An entry holds the L2 row/column of the neighbour's MAC and a 5-bit ageing field. | ✓ |
| Next-hop table | — | TACI type 13, 32 entries.  A gateway route points at a pair of entries (the encoding has no group of one), each carrying the egress netif, the gateway's L2 index and an optional external-IP index for NAPT. | ✓ |
| IPv6 routing / ND | RFC 8200 / RFC 4861 | Separate tables of the same shape (types 18-21, 8 routes, 256 ND entries); nothing is programmed. | ✗ |
| Multicast routing | RFC 1112 / RFC 4601 | TACI type 3 is an (S,G) hash that only applies in L3 mode; on an L2 bridge it does not steer traffic, which is why multicast uses L2 entries instead. | ✗ |
| DS-Lite / 6RD | RFC 6333 / RFC 5969 | Vendor tunnel engines (types 16/17, 8 entries each), left off in their config and not implemented here. | ✗ |

Route offload is off by default (`route_offload`).  A routed frame never
reaches the CPU, so it is not filtered, not tracked and not NAT'd: with
the switch on, the box is a plain L3 router for the routes it carries.
A route is only taken when every more specific route with a different next
hop is taken too, so a partly programmed table cannot shadow a route the
kernel sends elsewhere; when the connected prefixes do not fit, the
default route stays on the CPU.  The router identity is the netif entry's
MAC (`enHWRoute`), one entry per VLAN, so exactly one L3 interface per
VLAN is offloaded.

## L4 — transport offload and flow handling

| Feature | Standard | How it works | Done |
|---|---|---|---|
| TX checksum offload | RFC 791 / 793 / 768 | `CSCR` enables L3/L4 recalculation; the pkthdr describes each `CHECKSUM_PARTIAL` packet and sets `CSUM_TCPUDP`.  The ASIC does not fill the IPv4 header checksum, so the driver computes those 20 bytes itself.  Only unfragmented IPv4 TCP/UDP is described; everything else falls back to `skb_checksum_help()`. | ✓ |
| RX checksum verification | RFC 791 / 793 / 768 | The switch reports IPv4-header and TCP/UDP results in `ph_flags` bits 0/1.  The driver trusts them only for unfragmented IPv4 TCP/UDP and leaves everything else to software; bad frames are dropped. | ✓ |
| TSO / LSO | — | Needs the `SHORTCUT_LSO` pkthdr layout; the vendor 8198C kernel does not enable it either, so there is no reference implementation to match. | ✗ |
| GSO (software) | — | Segmented in the stack, with TX scatter-gather carrying the fragments.  There is no hardware segmentation unit. | ✓ |

| Flow offload | — | No `ndo_setup_tc` or flow-indirect offload path, so `tc` and nftables flows are handled in software only; `CONFIG_NET_SCH_TBF` is not built either, which leaves `tx_maxrate` as the only rate control. | ✗ |

## Descriptor format — legacy pkthdr/mbuf

The 8198C uses the legacy pkthdr/mbuf format.  A ring entry is a KSEG1
pointer with the OWN and WRAP bits in the low two bits:

| Constant | Value | Meaning |
|----------|-------|---------|
| `DESC_OWNED_BIT` | 0x0001 | OWN mask |
| `DESC_RISC_OWNED` | 0x0000 | RISC owns it (frame needs CPU action) |
| `DESC_SWCORE_OWNED` | 0x0001 | CPU owns it (descriptor is free to hand over) |
| `DESC_WRAP` | 0x0002 | Last entry of the ring |

Note the polarity: empty descriptors carry OWN=1, the RISC clears it for
a completed frame.

The port number travels out of band in `ph_portlist` in both directions
(egress mask on TX, ingress port on RX).  There is no in-frame CPU tag on
this interface: the Realtek tag needs port 0 strapped as GMII/RGMII
(`PITCR` bit 0, `P0GMIICR` bits 25/26, `MACCR1` bit 0), which is the
external-switch configuration.  On this board port 0 is an internal GPHY
(`PITCR` = 0) and setting the two tag bits leaves CPU-interface frames
untouched (measured).

```
struct pkthdr {                              // 32 bytes
    union {
        struct pkthdr *pkthdr_next;          // +0   TX free list
        struct mbuf   *mbuf_first;           // +0   RX first mbuf
    };                                       //      (ph_nextfree / ph_mbuf)
    u16 ph_len;                              // +4   length incl. 4-byte CRC
    u16 ph_queueId:3, ph_extPortList:4,
        ph_hwFwd:1, ph_isOriginal:1,
        ph_l2Trans:1, ph_srcExtPortNum:2;    // +6
    u16 ph_type:3, ph_vlanTagged:1,
        ph_LLCTagged:1, ph_pppeTagged:1,
        ph_pppoeIdx:3, ph_linkID:7;          // +8   parser results
    u16 ph_reason;                           // +10
    u16 ph_flags;                            // +12  CSUM_TCPUDP/CSUM_IP
    u8  ph_orgtos;                           // +14
    u8  ph_portlist;                         // +15  TX egress mask /
                                             //      RX ingress port
    u16 ph_vlanId_resv:1, ph_txPriority:3,
        ph_vlanId:12;                        // +16
    u16 ph_flags2;                           // +18
    u8  ph_resv_tx:4, ph_ipIpv6:1,
        ph_ipIpv4:1, ph_ipIpv4_1st:1;        // +20
    u16 ph_ipIpv6HdrLen;                     // +22
    u8  ph_pad[8];                           // +24  PTP fields on 8198C
};

struct mbuf {                                // 24 bytes, packed
    struct mbuf    *m_next;                  // +0
    struct pkthdr  *m_pkthdr;                // +4
    u16             m_len;                   // +8
    u8              m_flags;                 // +10  MBUF_EXT/PKTHDR/EOR
    u8              m_reserved2;             // +11
    u8             *m_data;                  // +12  frame buffer
    u8             *m_extbuf;                // +16
    u16             m_extsize;               // +20
    u8              m_reserved[2];           // +22
};
```

Ring entries are `u32`s holding a pointer plus the OWN and WRAP bits, in
uncached KSEG1 space: `(u32)kseg1(pkthdr)` for the pkthdr rings and
`(u32)kseg1(mbuf)` for the mbuf ring.  `m_data` points at the frame
buffer: linear TX converts it with `kseg1()`, RX writes straight into
`skb->data`, and SG fragments pass the page address and are
cache-flushed before the descriptor is handed over.

**Two TX rings.**  `CPUTPDCR1` is TX base + 1 KiB, `TXRINGCR = 0x3`,
`DMA_CR1` carries the ring length.  `CPUTPDCR0/1` read back as the
hardware's current descriptor pointer, not the programmed base, so a ring
base can never be verified by read-back.  `TXFD` in `CPUICR` must be set
per packet: with tail-aware mode on and no doorbell, descriptors queue but
never reach the wire.

**Six RX rings.**  `CPURPDCR0-5` point at the pkthdr rings and
`CPURMDCR0` at one shared, linear mbuf ring of `6 × 256` entries.  The
RISC takes the next mbuf from that ring regardless of which pkthdr ring
the frame lands on and rewrites `ph_mbuf` to the entry it used, so a
received frame is identified by mbuf index, not by descriptor slot.  The
classification chain is ingress priority → `CPUQIDMCR0` → CPU queue →
`CPUQDM` → RX ring; `QNUMCR` must give the CPU port six queues first.
`CPUQDM0/2/4` cover queues 0-5 only — the next 32-bit slot is `DMA_CR0`,
so programming queues 6/7 there would overwrite `HsbAddrMark`.

## Address spaces

Registers are reached through KSEG1 (`0xA0000000 | physical`).

| Block | Physical | KSEG1 | Description |
|-------|----------|-------|-------------|
| System registers | 0x18000000 | 0xB8000000 | GPIO, clock, reset, global interrupt mask |
| CPU interface | 0x18010000 | 0xB8010000 | Descriptor rings, interrupt mask/status |

## TACI — table access (0xBB804D00+)

| Offset | Name | Bits | Description |
|--------|------|------|-------------|
| 0x00 | `SWTACR` | bit0=start, bit1=add, bit2=del, bit3=force | Command |
| 0x04 | `SWTASR` | bits1:0 | Status |
| 0x08 | `SWTAA` | | Table address (**KSEG1 only**) |
| 0x20+ | `TCR0-7` | | Entry payload, 8 words |

Entry address: `0xBB000000 + (type << 16) + index * 32`.

| Type | Base | Table |
|------|------|-------|
| 0 | 0xBB000000 | L2 switching (`CMD_FORCE` to write) |
| 1 | 0xBB010000 | ARP (512 entries) |
| 2 | 0xBB020000 | IPv4 routing (8 entries, the last one the default) |
| 3 | 0xBB030000 | IP multicast (S,G), 256 entries, L3 mode only |
| 4 | 0xBB040000 | Netif (8 entries) |
| 5 | 0xBB050000 | External IP, 16 entries |
| 6 | 0xBB060000 | VLAN, indexed by VID (`CMD_ADD` to write) |
| 11 | 0xBB0B0000 | PPPoE, 8 entries |
| 12 | 0xBB0C0000 | ACL |
| 13 | 0xBB0D0000 | Next-hop, 32 entries (pairs for gateway routes) |
| 16 | 0xBB100000 | DS-Lite, 8 entries |
| 17 | 0xBB110000 | 6RD, 8 entries |
| 18 | 0xBB120000 | IPv6 routing, 8 entries |
| 19 | 0xBB130000 | IPv6 next-hop, 32 entries |
| 20 | 0xBB140000 | IPv6 neighbour (ND), 256 entries |
| 21 | 0xBB150000 | IPv6 multicast (S,G), 256 entries |

Every table operation goes through one engine: stop the lookup unit, fill
the TCRs, write the address, issue the command, restart it — the driver
serialises them with a mutex.

**L2 entry.**  256 rows of four 32-byte columns, so the index is
`row * 4 + column`; `row` is the XOR of the six MAC octets.  Word 0 holds
`mac[1..4]`, word 1 holds `mac[0]`, the member masks, `toCPU`, static and
aging bits, and the `fid`.  A zero member mask with `toCPU` clear drops
the MAC.

**VLAN entry (word 0).**

| Bits | Field |
|------|-------|
| 5:0 | `memberPort` (physical ports 0-5) |
| 8:6 | `extMemberPort` (CPU = bit 0) |
| 14:9 | `egressUntag` (physical ports) |
| 17:15 | `extEgressUntag` |
| 19:18 | `fid` |

The CPU is extension port 0, so "all ports plus CPU, untagged" is
`0xFE7F`; dropping the CPU bits yields `0x7E3F`, which kills all CPU
traffic once ingress filtering is active.

**IPv4 route entry (type 2).**  Word 0 is the prefix as a big-endian word
(`0xC0A80200` for 192.168.2.0; the byte-swapped value never matches).
Word 1, from bit 0: mask = prefix length − 1 (0 for the default), valid,
process (0 PPPoE, 1 direct L2, 2 ARP block, 4 CPU, 5 next-hop group,
6 drop), internal, netif (3 bits), then the process-specific field: the
ARP block start and end in units of 8 (bits 14-25), an L2 row/column
(bits 14-23), or the next-hop group start in pairs and its size encoded
as 2/4/8/16/32 → 0-4 (bits 11-13).

**ARP entry (type 1).**  Valid, the L2 index of the neighbour as
`row << 2 | column`, and a 5-bit ageing field.

**Next-hop entry (type 13).**  Type (0 = Ethernet), external-IP index,
egress netif, PPPoE session, L2 index.

**Netif entry.**  `mac18_0:19 | vid:12 | valid` in word 0,
`mac47_19 | enHWRoute:1 | enHWRouteV6:1` in word 1, the ingress ACL range
in word 2, `mtuV6:15 | mtu:15 | macMask:2` in word 3.  `enHWRoute` is what
makes the L3 stage handle frames addressed to this MAC; the lookup is by
VID, so a second entry on the same vid stops it from running.

## Driver init sequence

```
switch_reset()               // clock gate toggle (CM_ACTIVE_SWCORE)

switch_hard_reset()          // reset and clear every switch block
  -> MACCR = LONG_TXE, 12 MAC-group registers = 0
  -> VCR0/1, PVCR0-4, TEACR, FFCR, DOT1X*, GVGCR, SWTCR0/1, PLITIMR = 0
  -> PBVCR0/1 = 0, 30 PBVR rule registers = 0
  -> MSCR = 0
  -> PCRP0-8 = EnablePHYIf, PPMAR = 1
  -> SIRR = TRXRDY                      // before any MAC/PSCR access
  -> QIDDPCR = 0x11111, LPTM8021Q = 0, DSCPCR0-6 = 0, RMACR = 0, ALECR = 0
  -> SBFCR0-2, PBFCR0-5 (flow-control thresholds)
  -> PSCR: ELBPCR/ELBTTCR, ILBPCR1/2, 42 rate guarantees, 7x3 WFQ
  -> PATP0-11 = 0xFE12, TMCR &= ~ENHSBTESTMODE
  -> CPUICR test bits clear, CPUIISR drain, CPUQDM0-5 = 0,
     RMCR1P/DSCPRM0-1/RLRC = 0

switch_l2_init(mac)          // switch/L2 bring-up
  -> MSCR engines off, ALECR BIT(29), MSCR STP off, RMACR clear
  -> SWTCR1: NAT/Frag/L4 parse
  -> l2_table_clear(): MEMCR=0x7F, wait, MIB clear
  -> FFCR TOCPU bits clear
  -> PCRP0-4: MacSwReset + ExtPHYID + EnablePHYIf, STP forwarding (0-6)
  -> PCRP NwayAbility = all speeds (10H/10F/100H/100F/1000F)
  -> QNUMCR: two queues per port, six for the CPU; QOSFCR BIT(0),
     V4VLDSCPCR, DSCPCR clear, CPUQIDMCR0, UPTCMCR1
  -> MACCTRL1 CMAC_CLK_SEL
  -> l2_fdb_init(): broadcast (row 0) + CPU MAC (hash row), CMD_FORCE
  -> MACCR: INF_PAUSE|DIS_MASK_CGST|LONG_TXE, backoff clear,
            SYSCLK=100MHz, FCDSC=48 pages
  -> CSCR: allow bits clear, EnL3ChkCal|EnL4ChkCal set
  -> l3_init(): L3 tables cleared (MEMCR does not cover them), CPU default
     route at index 7, ALECR TTL-1 on
  -> MSCR = EN_L2 | EN_L3, PIN_MUX, IPV6CR1, LEDCR0/DIRECTLCR, ALECR PPPoE

switch_gphy_init()           // SRAM98C patches + NCTL DSP calibration
N-way restart                // PHY reg 9 |= 1000BASE-T FD, reg 0 restart

alloc_rings()                // pkthdr/mbuf pools, ring bases, CPUICR left off
netif_vlan_init(mac)         // netif entry, VLAN 8/9 = 0xFE7F, PVIDs,
```

## Programming order

Rules that span blocks.  Reversing one does not merely leave a feature off:
it breaks traffic, usually without an error.

| Rule | If reversed |
|---|---|
| `SIRR.TRXRDY` before any MAC or PSCR access | The PSCR block (leaky buckets, per-queue rate guarantees, WFQ) hangs the bus |
| After `MEMCR` clears the tables, re-create the netif, VLAN and static FDB entries | Every address becomes unknown, so traffic floods or is trapped until the entries exist again.  A missing VLAN entry is invisible from the data path: an unknown VID is trapped to the CPU |
| ACL default rules and the rule chain before `MSCR.EN_IN_ACL` | Blackhole: the default action of an empty engine is not permit |
| Ring base registers and the queue→ring map (`CPUQDM`) before `TXRINGCR` enables the rings | The RISC fetches uninitialised descriptors |
| `BSCR` budget before arming a `PCRP` storm meter | A zero budget blocks all broadcast |
| RX buffers sized for the MTU before a frame that large can arrive | RX truncates into the previous buffer size |
| The L3 tables cleared explicitly after `MEMCR` | `MEMCR` covers L2, VLAN, ARP/multicast and ACL only; a route left from an earlier boot goes live as soon as a netif enables routing |
| One netif entry per VLAN before any route names its index | The route carries a raw netif index; duplicate vids disable the L3 stage entirely |
| A route before the ARP entries inside it, and an L2 entry before the ARP entry | The ARP index is `block + host part`, so the block has to exist first; the ARP entry points at an L2 slot that must stay static |
| `ALECR.TTL_1Enable` before a route carries traffic | Without it a routed frame keeps its TTL |
| Route entries written longest-prefix-first, the default at index 7 | Index order is lookup order; a default route at a lower index would shadow everything |
